# 8070 Windows 安装包

安装器界面更新：名称为“皮卡丘手机工作台 / Pikachu Phone Workbench”，启动时先选择简体中文或 English，固定近黑底加 `#FF70B6` 粉色，不提供主题切换。小图标直接使用原透明 PNG，避免浅色底块；界面资源位于 `tools/installer_8070/assets/`。安装与卸载身份、后台发现注册表及控制协议沿用原值，已有安装继续使用原路径，新安装默认 `Programs/PikachuPhoneWorkbench`。输出为 `releases/皮卡丘手机工作台-<版本>-安装.exe`，旧安装包保留。工作台页面另增加与配套皮卡丘构建联动的四主题桥，见 [接入协议](../PIKACHU_8070_CONTROL_PROTOCOL.md)。当前版本 v0.1.21；新增本地持久短信调度和单条结果核验。

当前已交付 v0.1.19 皮卡丘集成后台包。v0.1.20 修复设备重连时目标 USB 隧道残留问题。v0.1.21 新建短信支持立即和定时任务；离线专项回归通过，仍需用户进行真实短信验收。目标：Windows 10/11 x64，无需目标电脑预装 Python、Node 或 Git；需使用已接入后台控制协议的皮卡丘客户端。8070 与平级 VNC 项目使用不同 AppId 和目录。

当前后台专用构建与验收：

## 打包前强制检查

先确认交付范围与目标构建：当前 8070 后台专用包为 v0.1.19，目标新包为 v0.1.21。皮卡丘宿主负责菜单、IPC 和启动/关闭；8070 提供后台、网页和 `host_control.py` 协议。宿主的源码或安装包不会因重打 8070 包而更新，反之亦然。皮卡丘菜单的 `preload.cjs` 修复需要进入皮卡丘自己的构建；8070 控制器或网页变更需要进入 8070 包。联动网页主题桥只用于皮卡丘内嵌的 `http://127.0.0.1:8070/` 顶层页面；安装器固定粉色，不跟随宿主主题。

1. **确认版本和工作树范围。** 核对根目录 `VERSION`、目标文件名、当前分支、所有已修改/未跟踪文件及用户数据边界。构建器会用 `git ls-files iphone_batch` 取得文件名，再从当前工作树复制已跟踪文件；少数未跟踪文件被硬编码列入。其他未跟踪源码不会自动打包。打包清单必须逐项确认新增源码已纳入，且诊断、测试、`.device-data`、账号、配对和密钥没有进入载荷。
2. **使用全新 stage。** 默认构建创建带时间戳的新 stage。禁止对旧 `--repack-stage` 目录做正式交付：复用 stage 不重新复制应用源码，可能把旧 controller/dashboard 与新文档或新版本混在一起。只有明确的纯安装器资源迭代、确认载荷源码完全不变时才允许复用；重打前对照 stage 与当前源码文件哈希。不要手工覆盖已安装目录来代替正式构建。
3. **核对专用模式和依赖。** 本次与皮卡丘集成的包必须使用 `--host-only`；不得意外带回 Electron 或独立启停入口。确认锁定依赖、Python/Node/CRT 来自预期构建环境，策略文件为 `protocol:1, mode:pikachu-only`，安装发现注册表仍为 HKCU 64 位协议 1。
4. **先跑源码专项回归，再构包。** 对本次变更涉及的控制协议、控制器、工作台页面/主题桥和宿主协议分别运行项目既有检查；设备连接相关代码先核对当前已知 30 秒画面超时是否仍未解决，不能把打包隔离测试称为实机通过。不要在打包检查中启动真实 USB 后台或操作手机。
5. **检查构建器的隔离验证和载荷清单。** 构建器必须在移除开发环境 PATH 后，以 stage 内 Python/Node/Tcl/CRT 启动零设备临时工作台，验证签名访问、未授权启停拒绝、后台模拟父子进程退出、版本和页面入口；manifest 要逐文件 SHA256，并确认无业务数据/凭据。检查日志及报告中的 `project=8070`、`pikachu_host_only=true`、`runtime_data_bundled=false`。
6. **实际安装验证必须先检查冲突。** `check_8070_installer.py` 会拒绝覆盖任何已有同 AppId 登记，并会在隔离中文/空格目录安装后卸载。先确认 8070 正式安装登记和目标路径，避免影响用户当前安装。中英文安装器文案各自检查；最终 EXE 再计算 SHA256、核对 `.sha256` 与 JSON 报告，保留旧包，不直接覆盖或删除。真实短信测试只用用户明确指定的测试号码，由用户确认发送。
7. **交付边界逐项报告。** 明确标注构建源码版本/提交、包文件/大小/SHA256、运行时和隔离测试结果、皮卡丘宿主对应构建、未通过的真机验收（当前设备画面 30 秒超时），以及是否实际安装。没有用户明确要求时不启动/停止运行中的后台、不操作手机、不提交推送。

### 两项目的职责关系

- **8070 项目**（本仓库）维护后台控制器、HTTP 工作台、设备投屏/输入和安装包控制协议；D 盘 `PikachuPhoneWorkbench` 是安装运行副本，和源码开发环境分离。
- **皮卡丘项目**维护 Electron 宿主、右键菜单、preload IPC 和主题选择。宿主通过注册表发现 8070 安装目录，调用固定的 `runtime/python.exe` + `iphone_batch/host_control.py`；不得硬编码 D 盘路径。
- 8070 网页只在皮卡丘 Apple 内嵌 WebView 页面打开时接收宿主主题桥。此关系不意味着共享开发缓存、Python 环境或后台进程；两边需要分别构建、分别核对实际加载入口，再做跨项目联调。
- 开发环境必须按正常后台控制器启动：控制器会先建立/检查共享 USB 隧道，直接运行 `Start.ps1` 中的 dashboard 并不等价。设备断开后 tunneld 可能仍列出旧 UDID 条目；v0.1.20 在目标设备的新投屏会话前只取消并重建该设备的隧道。不得清空其他设备隧道或 Apple 配对记录代替恢复。

```powershell
.venv\Scripts\python.exe tools/build_8070_installer.py --host-only
.venv\Scripts\python.exe tools/check_8070_installer.py "releases/皮卡丘手机工作台-0.1.21-安装.exe" --language chinesesimp
.venv\Scripts\python.exe tools/check_8070_installer.py "releases/皮卡丘手机工作台-0.1.21-安装.exe" --language english
```

新模式无 Electron、独立启动器、桌面或开始菜单启停入口。安装器将实际路径、版本和控制协议写入当前用户 64 位注册表；卸载清理登记。升级时清理固定的旧客户端程序目录及快捷方式，不清理业务数据。皮卡丘通过三种固定 JSON/stdin 命令控制后台，安装模式下直接启动 dashboard.py 或无授权启停被拒绝。具体约定见 [接入协议](../PIKACHU_8070_CONTROL_PROTOCOL.md)。注册表验证使用隔离测试目录临时登记，结束后卸载；不覆盖已有同 AppId 的安装。

当前检查除了内置运行时、实际加载的 C++ DLL 路径、零设备签名 HTTP、版本和短信入口，还核验签名 status、无授权 start/stop 拒绝及无授权 dashboard 启动拒绝。37 项 Python 回归包含真实后台方法通过 stdin 传递 serve 凭据并关闭隔离服务子进程。双方跨语言与菜单交互测试由皮卡丘项目完成。实机 USB 启停尚未在新安装目录验证，不自动操作正在使用的手机后台。

以下保留 v0.1.18 独立桌面包的重建说明；其桌面入口不用于当前集成模式。

使用项目 Python 3.13 虚拟环境运行：

```powershell
.venv\Scripts\python.exe tools/build_8070_installer.py --electron <Electron-dist目录> --iscc <ISCC.exe路径>
.venv\Scripts\python.exe tools/check_8070_installer.py releases/PhoneWorkbench8070-0.1.18-Setup.exe
```

Electron 参数仅指定开源运行时目录，不复制其上层应用源码、用户资料或登录。生成目录为 `releases/`，构建缓存和逐文件 SHA256 清单位于忽略的 `iphone_batch/.device-data/installer-build/`。安装包包含 Python/Tcl、项目依赖、Node、Electron、官方 x64 VC143 CRT 和独立桌面启动页；安装目录内 Python 通过 `_pth` 隔离加载，不使用目标电脑 Python。CRT 默认取 Visual Studio BuildTools 的可分发目录，也可通过 `--crt` 指定同类官方目录。桌面入口沿用本机 HMAC 校验，各电脑自行创建凭据。

验证包括：清理开发环境 PATH，加载主要原生依赖、核对锁定版本及实际加载的 CRT DLL 路径，启动零设备临时端口工作台，检查签名请求 200、未签名请求 403、页面版本及新建短信入口。随后将最终 EXE 实际安装到含中文和空格的独立目录，重复上述检查，再卸载。额外使用安装后的 Python 和真实后台管理代码启动隔离的模拟服务及子进程，验证状态查询、彻底关闭和进程退出；仅替换 USB 隧道入口及模拟脚本目录。验证不会发现或操作手机，也不使用开发后台端口。已有同 AppId 安装时验证器拒绝运行，避免覆盖用户安装。

Apple USB 驱动与服务不内置；新电脑需通过 Apple 官方安装程序准备，手机需解锁、信任电脑及开启开发者模式。首次开发者镜像准备可能需要网络；共享隧道需管理员授权。当前安装器未进行发行商代码签名。隔离安装测试不代替另一台物理电脑的 Apple 驱动、USB 和手机实机验收。

安装器按当前 Windows 用户安装，不自动启动。卸载不递归清理业务数据。v0.1.18 首次使用点击独立启动页的“启动并打开工作台”；v0.1.19 起改由皮卡丘“打新增”右键菜单启停，页面通过原有苹果入口打开。关闭宿主窗口保留后台。v0.1.21 的短信任务保存在本机 `.device-data/workspace/sms-tasks`；意外关停后，发送前单元续跑，发送请求已记录但回执缺失的单元进入待核对，不自动重发。屏幕 30 秒超时等实机问题不由离线包检查判定。
