## 最新界面、输入与 GPT 导出

- 顶部品牌横幅已移除。阅读区横幅最多两行；第一行显示设备编号、短信与译文、对方号码，读取和刷新按钮始终贴右；第二行是待跟进和联系人资料。极窄时信息区域横向滚动，不产生第三行。联系人选择和资料卡片使用浮层，避免被滚动容器裁切。
- 整体为皮卡丘闪电深色主题；无缝涂鸦纹理只铺在英文与译文气泡区域。实时画面为纯深色，未加载时保留中央闪电。发送按钮为纸飞机。中文译文 18px、英文 15px，工具文字正常 15px，窄窗口至少 14px，状态提示 14px。
- 回复区常驻，只保留表情按钮、文字输入框、发送按钮；没有“人工回复”标题、下方提示、复制按钮、独立翻译按钮或回译展示区。
- 中文第一次 Enter 在原输入框转为英文，第二次 Enter 直接发送；英文直接 Enter 发送。Shift+Enter 换行，输入法确认及按住 Enter 的重复事件不发送。发送前前后端均禁止中文；结果不确定不自动重试。
- 手机发送仅在当前已核验号码会话中聚焦、输入、发送，不再为聚焦重新打开收件人页面；号码、草稿、上下文和输入正文检查继续保留。本次验证使用模拟接口，没有发送真实短信。
- 表情包含玫瑰、郁金香、樱花、向日葵、花束等。表情面板挂到页面浮层，点击按光标位置插入；尚未选择会话时也可输入和插入表情，发送仍禁用。实际浏览器鼠标点击测试覆盖未选会话插入玫瑰、已选会话插入花束及普通表情。
- 联系人资料改为“去汇总”：`gpt_export.js` 导出当前已保存的双方原文，标注我方/对方，保留重复消息，排除附件，加入资料分析要求；`gpt_bridge.py` 写入 Windows 剪贴板，`gpt_browser.cjs` 使用独立 Chrome/Edge 配置打开 ChatGPT，仅填入输入框，不自动发送、不覆盖已有草稿。
- GPT 草稿填入使用本机 Node 的 WebSocket/CDP，无新增浏览器自动化依赖。独立登录数据位于被 Git 忽略的 `.device-data/chatgpt-browser`。本地 Chromium 测试已验证 Unicode、多行和保留草稿；实际 ChatGPT 页面测试返回 `page_not_ready`，剪贴板已复制，未发送。需页面正常加载或登录后复验，不能宣称实际网页填入已成功。
- 最近 84 项 Python 回归通过。`test_chat_composer.cjs` 验证表情、原地翻译、第二次回车、中文/输入法/重复按键拦截及不确定发送禁止重试；`test_reading_layout.cjs` 在 5 种窗口宽度验证横幅最多两行和资料浮层可见。

## 2026-10-18 简化交互

- 手机列表按两列排列，每台使用宽 20px 的 iPhone 轮廓图标，右上角显示红色数字，按最近一次扫描可见的短信通知卡片计数；同一联系人多张卡片分别计数，不解析分组内短信条数。设备详情可悬停查看。
- 新发现通知卡片时由 Windows 后端异步播放系统通知提示音；同一卡片的重复扫描不重响，数量不变但出现新卡片也提示。声音遵循系统音量设置，不依赖浏览器播放权限。
- 阅读区“此联系人待跟进”按设备与联系人保存；优先用规范化完整号码作为联系人标识，同一联系人的多份读取快照不重复计数。设备图标显示该手机已勾选的联系人数量，勾选增加、取消减少。右键“待跟进 / 无”保留为人工手机备注，不额外增加联系人数量；没有关联联系人时旧手机级标记不迁移为联系人记录。
- 设备图标右键可编辑编号。编号、联系人勾选、人工备注和排序方式按预览/真实设备分别保存到当前浏览器。
- 设备列表支持切换“待跟进优先”（已勾选联系人数量降序）和“未读消息数优先”（通知卡片数降序）；同优先级保持原设备顺序，排序不改变设备编号或当前选中设备。20 台预览地址为 `http://127.0.0.1:8070/#preview-devices`，选中手机可切换 3 位示例联系人测试勾选和计数，发送和真机操作禁用。
- 点击手机图标下的待跟进数量，展开该设备联系人列表；点击有完整号码的联系人，调用 `open`，检查手机草稿后以 Command+N、粘贴号码、Return 确认收件人，进入后复核号码，再读取、翻译、归档。此路径不再要求联系人仍在未读列表中，不发送短信。浏览器有草稿时阻断切换。预览仅模拟选择，不操作手机。
- “刷新已保存记录”仅重载电脑归档，不读取手机；“读取当前会话”才读取手机现场。快捷打开可能触发历史补读/数据库兜底，手机已打开不代表阅读区已完成翻译。
- 阅读区从“短信与译文”横幅开始，横幅吸顶。已移除上方的当前会话标题、说明、历史会话选择框和原文显示开关及其界面逻辑；原文与译文同时显示。当前阅读记录使用内部会话 ID 管理，刷新归档优先保留当前记录，快捷打开和发送后的阅读更新不依赖已移除的选择框。
- 快捷打开相关 77 项 Python 模拟回归及前端计数、列表、打开请求、草稿保护检查通过；本次未连接真机复验。
- 当前选中手机暂停后台通知扫描，切换离开后恢复；其数字保留上次扫描结果，不因选中自动清零。其他手机最多 4 台并行，取消每轮 30 秒等待和首次启动延迟，扫描完成立即回到队尾；空闲名额随任务完成继续补入，按队列公平轮询。
- 用户在投屏中手动进入短信会话，再点击“读取当前会话”，在阅读区翻译和人工回复。已移除界面的通知打开和未读会话打开入口。
- 卡片计数按本次实际扫描结果更新，不沿用旧自动打开流程的 opened 状态过滤；卡片仍存在就计数，消失后下一次扫描移除。
- 后台发现仍需逐台进入通知中心，不是无触屏的推送监听。当前选中手机的数字在离开并重新扫描前可能滞后。
- 69 项相关模拟回归及前端语法、快捷键和剪贴板检查通过；本次未进行真机操作。下文为此前实现及历史验证，交互以本节为准。

2026-10-10 的完整实现、探索结果、实机验证和恢复说明见 [详细会话存档](../SESSION_ARCHIVE_2026-10-10.md)。该存档中的 30 秒间隔和点击通知自动打开流程属于历史实现，当前规则以上节为准。

固定本地地址为 http://127.0.0.1:8070/ 。选择手机后，可以读取当前会话并自动翻译，汇总对方资料，生成中文回复的英文译文及中文回译。

未读横向列表由“刷新未读”更新。原生扫描逐个等待元素回执后推进，不用截图或 OCR；扫描结束需核验连续两个起点元素。连续两次完整遍历、内容一致时显示已完成；超时、达到元素限额、回执丢失或列表变化时显示未确认完整，保留已发现联系人，不能将部分结果当作全部未读。完整性针对当前打开的列表或筛选视图，不涵盖其他短信筛选分类。刷新会在确认无手机输入草稿后右滑返回列表。列表仅有姓名而没有完整号码时仍显示姓名，但暂不能自动打开；完整号码用于唯一核验收件人。

中文输入按 Enter 生成英文及回译，再按 Enter 发送。粘贴不含中文的英文、链接、数字或表情，Enter 直接发送。Shift+Enter 换行，输入法确认键不触发。界面、后端和手机发送前均禁止中文；回复内容、完整号码、当前会话及输入框核验成功才触发一次发送。发送结果不明确时禁止自动重试。历史归档仅用于阅读和汇总，发送须先读取当前号码会话。

`.device-data/workspace/replies` 保存上下文、人工中文、机器英文、最终发送内容、中文回译和发送状态。只有 `sent_verified` 是已确认发送的学习案例；草稿、失败和结果不确定记录不能当作成功案例。资料汇总保存在 `workspace/profiles`，每项保留对方原文依据；没有对方消息依据的模型条目会被丢弃。

原生会话读取仅覆盖本次可遍历消息，界面注明历史范围限制。图片消息不自动翻译。密钥和手机数据均放在忽略提交的 `.device-data` 内。
